# DXF 尺寸解析分頁設計

## 目的

在長袖 DXF GUI 新增分頁，從一個資料夾的 DXF 袖片讀出各尺寸袖長與袖口寬，預覽數值後以批名寫入目前尺寸 JSON，減少逐件測量與手動建款。

## 範圍與限制

- 遞迴掃描所選資料夾及所有子資料夾中的 `.dxf` 檔。
- 以檔名辨識尺寸，沿用現有的尺寸正規化與 JSON 結構。
- 使用既有袖片分析器辨識袖片；袖口片不作為來源袖片。
- 袖口平量顯示為分析所得袖口開口寬的一半；JSON `cuff_width_mm` 寫完整袖口開口寬。
- 解析結果先顯示在表格；只有按「寫入 JSON」才合併資料。
- 未辨識尺寸及袖口片／無法分析的檔案列出原因並略過；若同尺寸有多個可辨識袖片，列出原因且不寫入該尺寸。
- 寫入款式沿用現有批次 JSON 合併規則：批名作款式名；同名款式更新，不同款式新增；保留其他款式與預設設定。
- 遞迴掃描所選資料夾及所有子資料夾；不產生 DXF、不修改 Excel 批次流程。

## 實作方式

1. 新增「DXF 尺寸解析」分頁，提供資料夾選擇、資料夾拖放、批次名稱、目前 JSON 路徑、解析表格、解析與寫入按鈕及結果紀錄。拖放資料夾會切換至該分頁並立即遞迴解析。
2. 表格欄位沿用參考圖：尺寸、袖長（mm）、袖口平量（mm）、寫入 JSON 袖口寬（mm）。
3. 遞迴掃描所選資料夾中的 DXF，從檔名辨識尺寸，不要求父資料夾名稱符合尺寸；只分析檔名含「袖」且不含「袖口」、也不以 `#` 開頭的標準檔案，再以既有 `read_dxf` 與 `find_sleeve` 驗證袖片輪廓；依尺寸彙整唯一有效袖片，同尺寸多個有效袖片不任意挑選其中一件。
4. 寫入時使用既有 `SizeTable` 與命名款式合併流程，透過其備份與驗證機制保存 JSON。

## 方案比較

- **遞迴掃描整個資料夾（已選）**：不用先整理子資料夾，可完整找出來源檔；需回報重複或無法辨識的檔案。
- **手動多選 DXF**：可排除不需要的檔案，但每次需維護選取清單，流程較繁複。

採用遞迴掃描，依使用者選擇，並保留逐檔錯誤紀錄及相對路徑，讓使用者修正資料夾內容。
